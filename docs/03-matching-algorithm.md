# 03. 매칭 엔진 설계 — 그래프 이론 & TTC 알고리즘

## 1. 문제의 수학적 모델링

### 1-1. 주택시장 교환 문제 (Shapley-Scarf Housing Market)

본 서비스의 매칭은 1974년 Shapley & Scarf가 정식화한 **주택 교환 시장(housing market)** 문제와 정확히 일치한다:

- 각 참여자(agent)는 집 1채를 **소유**하고 있다
- 각 참여자는 시장의 집들에 대한 **선호 순서(preference ordering)** 를 갖는다
- 목표: 모두가 지금보다 나쁘지 않고(개인 합리성), 더 나은 재배분이 불가능한(파레토 효율) 교환을 찾는 것

이 문제의 해법이 David Gale이 제안한 **TTC(Top Trading Cycles)** 알고리즘이며, 다음이 수학적으로 증명되어 있다:

| 성질 | 의미 (서비스 관점) |
|---|---|
| **개인 합리성** | 누구도 매칭 참여로 손해보지 않음 → "매칭 결과가 내 등록 조건보다 나쁘면 애초에 제안되지 않는다" |
| **파레토 효율성** | 더 나은 재배분이 존재하지 않음 → 플랫폼이 찾은 매칭이 최선임을 보장 |
| **전략 무관성 (strategy-proof)** | 선호를 거짓으로 등록해도 이득이 없음 → 회원이 솔직하게 조건을 입력할 유인 |
| **유일한 코어 배분** | 어떤 소그룹도 이탈해서 자기들끼리 더 잘할 수 없음 → 플랫폼 밖 이면거래 유인 차단 |

### 1-2. 그래프 표현

**방향 그래프 G = (V, E)** 로 모델링:

- **정점 V**: 인증된 소유주의 물건 (동·호수 단위)
- **간선 E**: `u → v` = "u의 소유주가 v를 매수 희망 조건으로 수락 가능"
  - 간선 생성 조건 (하드 필터, 전부 만족해야 간선 생성):
    1. v의 단지·동·층·평형·향이 u의 희망 조건에 부합
    2. v의 희망 매도가 ≤ u의 예산 상한
    3. 이사 가능 일정의 교집합이 최소 겹침 기간(예: 2주) 이상
    4. v의 소유주도 매도 의사 활성 상태
- **간선 가중치 w(u→v)**: 소프트 선호 점수 (아래 3절)

**매칭 = 이 그래프에서 정점-서로소(vertex-disjoint) 사이클들의 집합을 찾는 것.**
사이클 `A → B → C → A` 는 "A가 B의 집을 사고, B가 C의 집을 사고, C가 A의 집을 산다"는 3자 순환거래를 의미한다.

## 2. 알고리즘 파이프라인

```
[1] 후보 간선 생성 (하드 필터)
      ↓
[2] 가중치 계산 → 각 정점의 선호 순위 리스트 확정
      ↓
[3] TTC 라운드 실행 (사이클 탐색·확정·제거 반복)
      ↓
[4] 사이클 실행 가능성 검증 (일정·가격 정산 시뮬레이션)
      ↓
[5] 매칭 제안 발송 → 전원 수락 시 거래 개시
```

### 2-1. TTC 실행 (3단계 상세)

```
반복:
  1. 남아있는 각 정점 u가 자신의 선호 1순위 정점 top(u)를 가리키는
     함수 그래프(functional graph)를 만든다 (각 정점의 진출차수 = 1)
  2. 함수 그래프에는 반드시 사이클이 존재한다 (유한 그래프에서 증명됨)
     → 사이클 탐색으로 모든 사이클 발견
  3. 발견된 사이클의 참여자들을 매칭 확정 후보로 빼내고 그래프에서 제거
  4. 남은 정점들의 선호 리스트에서 제거된 정점을 삭제하고 1로 복귀
종료: 더 이상 간선이 없거나 모든 정점이 제거될 때까지
```

- **사이클 탐색 기법**: 함수 그래프에서는 각 정점에서 포인터를 따라가며 방문 표시만 해도 O(V)에 모든 사이클을 찾을 수 있다 (Floyd/방문배열 기법). 일반 그래프 분석용으로는 Tarjan SCC → SCC 내부에서 Johnson 알고리즘으로 단순 사이클 열거를 사용한다.
- **자기 자신 포함**: "지금 집 유지"를 선호 리스트의 마지막에 넣으면 (u→u 셀프루프) 개인 합리성이 자동 보장된다.

### 2-2. 사이클 길이 제약 (실무 제약)

이론상 사이클 길이 제한이 없지만, **참여자가 많을수록 한 명의 변심으로 전체가 깨질 위험**이 커진다.

- 운영 정책: **사이클 길이 k ≤ 4 (권장 2~3)** 로 제한
- 길이 제한 TTC는 NP-hard가 되므로 (신장 교환 매칭과 동일한 구조), 다음 중 택일:
  - **v1**: k=2 (맞교환) + k=3만 탐색 — 단순 열거로 충분히 빠름 (단지 규모 수천 정점에서 문제없음)
  - **v2**: 정수계획법(ILP)으로 "가중치 합 최대의 서로소 사이클 집합" 최적화 — 신장 교환 프로그램(kidney exchange)에서 검증된 방식 (cycle formulation + branch-and-price)
- **체인 확장**: 신규 진입자(무주택 매수자) 또는 순수 매도자(이탈자)가 있으면 사이클이 아닌 **체인**도 가능 — Phase 2에서 도입 (신장 교환의 altruistic donor chain과 동일 구조)

### 2-3. 실행 주기

- **배치 매칭**: 매일 1회 야간 배치로 전체 재계산 (참여자 풀을 모아서 돌릴수록 매칭 품질↑ — thickness 확보)
- **실시간 알림**: 신규 가입/조건 변경 시 즉석 2-사이클(맞교환)만 실시간 탐지해서 푸시
- 매칭 제안 후 **48시간 수락 대기** → 1명이라도 거절 시 해당 사이클 해체, 나머지는 다음 배치에 자동 재진입

## 3. 가중치 설계 (매물 컨디션 반영)

간선 가중치 `w(u→v)` = u가 v로 이동할 때의 만족도 점수. **각 정점의 선호 순위는 이 점수의 내림차순**으로 결정된다.

### 3-1. 점수 구성

```
w(u→v) = Σ (항목별 점수 × u가 설정한 항목 가중치)

항목:
  ① 위치 선호 일치도   : 동/층/향이 u의 희망과 일치하는 정도 (0~1)
  ② 평형 일치도        : 희망 타입 정확 일치=1, 인접 타입=0.5
  ③ 컨디션 점수        : v의 인테리어 등급 (올수리=1.0, 부분=0.7, 기본=0.4, 수리필요=0.1)
                          × 시공연도 감가 (연 5%)
  ④ 가격 적합도        : 예산 대비 여유 (예산 상한에 가까울수록 감점)
  ⑤ 일정 호환도        : 이사 가능 기간 겹침 일수 (길수록 가점)
  ⑥ 점유 리스크        : 공실/자가=1.0, 임차 만기 임박=0.6, 만기 원거리=0.2
```

### 3-2. 사이클 스코어와 타이브레이크

여러 사이클 조합이 가능할 때의 우선순위:

```
사이클 점수 = 참여 간선 가중치의 합
              × 사이클 안정성 계수 (짧을수록 ↑: k=2는 1.0, k=3은 0.9, k=4는 0.8)
              × 일정 여유 계수 (전원 일정 교집합이 길수록 ↑)
```

- ILP 목적함수: `maximize Σ (사이클 점수)` — 매칭된 사람 수와 만족도를 동시에 최적화
- 동점 시: 대기 기간이 긴 회원 우선 (선착순 공정성)

### 3-3. 가격 차액 정산

순환거래에서 각 물건의 가격이 다르므로 **정산 그래프**가 필요:

- 사이클 확정 시 각 참여자의 순지불액 = (매수가) − (매도가) 자동 계산
- 잔금일 동시 실행 시나리오 표 자동 생성 (법무사 검증용)
- 하드 필터에서 이미 예산 검증이 끝났으므로 정산 불능 사이클은 생성되지 않음

## 4. 콜드 스타트 전략

매칭 시장의 고질 문제 = 초기 유동성(thickness) 부족.

1. **단지 1곳 집중 공략**: 세대수 많고 평형 다양한 단지 1곳에서 시작 (평형 사다리 존재 = 사이클 형성 확률↑)
2. **"매칭 가능성 미리보기"**: 가입 즉시 "당신의 조건과 맞는 잠재 상대 n명" 노출 (실명 비공개) → 프로필 완성 유도
3. **편도 수요 흡수**: 순수 매도자/매수자도 등록 받아 체인 재료로 활용
4. **중개사 제휴**: 협력 중개사가 보유한 매물·수요를 시드 데이터로 유입

## 5. 기술 구현 노트

- **프로토타입**: Python + NetworkX (`simple_cycles`, SCC) — 수백~수천 정점 규모는 즉시 처리 가능
- **최적화 단계**: OR-Tools / PuLP로 ILP 사이클 선택
- **매칭 엔진 분리**: 웹 서버와 분리된 워커 (큐 기반, 야간 배치 + 온디맨드)
- **재현성**: 매 배치의 입력 스냅샷·결과·미채택 사이클을 로그로 보존 (CS 대응 + 알고리즘 개선 데이터)
- **테스트**: 시뮬레이션 하네스 — 가상 단지(세대 분포·선호 분포 파라미터화) 생성 → 매칭률/사이클 길이 분포 측정
