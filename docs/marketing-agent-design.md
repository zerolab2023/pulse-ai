# Pulse-AI 마케팅 에이전트 설계서
## 안양 건강검진 내과 · 네이버 블로그 담당 마케터 버전

> **목적**: 병원(안양 지역 건강검진 내과)의 네이버 블로그를 운영하는 "AI 마케터 에이전트"를 만든다.
> 이 문서는 (1) 페르소나·톤앤매너, (2) 네이버 블로그 알고리즘의 실제 동작, (3) 가장 빠른 성장 전략,
> (4) 에이전트 기술 아키텍처, (5) 효과를 스스로 판별하는 **클로즈드 루프 평가 알고리즘**,
> (6) 이 접근이 타당한지에 대한 비판적 검토를 담는다.

---

## 0. 한 장 요약 (TL;DR)

- **채널 특성**: 네이버 블로그는 "팔로워 수"가 아니라 **검색 상위노출 → 방문자 유입 → 예약(DB) 전환**이 성과다.
  쓰레드의 "팔로워 500"에 대응하는 목표는 **"타깃 지역 키워드 상위노출 + 월 순방문 + 예약 문의 수"**로 재정의한다.
- **알고리즘 구조**: `C-Rank(블로그 신뢰도) × D.I.A.+(개별 문서 품질)` 이중 평가. 2026년 기준 하이퍼클로바X 기반
  문서 해석이 강화되어 **"구조화된 정보 + 체류시간 + 원본성"**이 핵심이다.
- **최대 리스크**: **의료광고법(의료법 제56조)**. 건강검진·내과는 치료경험담/후기형 콘텐츠가 곧바로 위법이 될 수 있다.
  에이전트에 **컴플라이언스 게이트를 하드 제약으로** 넣는 것이 성능보다 우선한다.
- **성장 전략**: 초기 저지수 블로그는 대형 키워드 대신 **롱테일 지역 키워드**("안양 인덕원 건강검진 비용" 등)로
  상위노출을 선점하고, 주제 집중도(내과·건강검진)를 쌓아 C-Rank를 올린다.
- **클로즈드 루프**: 발행 → 지표 수집(노출·체류·전환) → 주기별 평가 → 전략 파라미터 갱신 → 재발행.
  주기는 **콘텐츠 단위(발행 후 7/14/28일), 채널 단위(주간), 전략 단위(월간)**의 3중 루프로 설계한다.

## 1. 페르소나 & 톤앤매너

### 1.1 에이전트 페르소나
- **정체성**: "안양에서 10년째 검진받는 이웃 같은 병원 마케터." 의료진이 아니라 **환자 관점의 안내자**.
- **1인칭 화자 규칙**: 원장(의료인) 명의로 나가는 글과, 마케터/블로그 운영자 명의 글을 **명확히 분리**한다.
  - 의학적 판단·진단·치료효과 서술 → **반드시 의료인 감수** 후 의료인 명의.
  - 생활정보·검진 준비 팁·주차/동선/비용 안내 → 운영자 명의로 자유도 높게.

### 1.2 타깃 독자별 톤 (학습해야 할 화법)
| 독자 | 관심사 | 톤앤매너 |
|---|---|---|
| **검진 대상 일반인**(3040 직장인·주부) | "국가검진 뭐 챙겨야 하나", "비용", "공복 시간" | 쉽고 친절, 체크리스트/표 중심, 불안 자극 금지 |
| **부모님 검진 챙기는 자녀**(4050) | "종합검진 항목 차이", "위/대장 내시경 수면 여부" | 비교·근거 중심, 안심시키는 어조 |
| **병원장/원장 관점** | 신뢰·전문성·과잉진료 오해 방지 | 절제된 전문가 톤, 근거·수치 제시, 과장 배제 |
| **동종 마케터/DB마케팅 관점** | 전환·리드·상담 유도 | CTA는 "정보 제공 → 상담 연결" 순, 강매 금지 |

### 1.3 학습해야 할 "성공한 병원 블로그"의 공통 패턴 (리서치 기반)
1. **상위노출 자체보다 "이탈 없는 글"** — 유입돼도 몇 초 만에 나가면 무의미. 체류시간이 곧 순위.
2. **원장 스토리텔링** — "원장이 어떤 사람이고 어떤 철학을 갖는가"가 팬(재방문)을 만든다.
3. **환자 여정 설계** — 증상 인지 → 해결법 탐색 → 치료 필요성 인식 → 근처 병원 탐색의 흐름에 맞춰 글을 배치.
4. **롱테일 우선** — 지수 낮을 때 대형 키워드는 못 이긴다. 전환율 높은 세부 키워드부터.

## 2. 네이버 블로그 알고리즘 (에이전트가 최적화할 대상 함수)

에이전트의 목적함수는 사실상 아래 두 점수를 동시에 올리는 것이다.

### 2.1 C-Rank — "블로그(채널) 신뢰도"
- 평가 축: **주제 집중도, 콘텐츠 생산의 꾸준함, 사용자 반응, 원본성, 채널 활동 기간.**
- 함의: **"내과·건강검진"이라는 한 주제로 꾸준히** 쌓아야 한다. 잡블로그(맛집+여행+병원)는 불리.
- 에이전트 규칙: 발행 주제의 **80% 이상을 검진/내과 도메인**으로 고정. 주제 이탈률을 지표로 감시.

### 2.2 D.I.A.+ — "개별 문서 품질" (2026, 하이퍼클로바X 기반 강화)
리서치로 확인된 품질 신호:
- **체류시간이 1순위** — 상위노출 글 평균 최소 **1분 30초 이상**.
- **문서 길이** — 정보성 글 기준 **1,500~2,000자** 내외.
- **직접 촬영 고화질 사진 6~13장 + 15초 이상 동영상(모먼트)**.
- **구조화** — 목차/소제목/표/요약. AI가 "답변 출처"로 채택하기 좋은 형태.
- **원본성·검증 가능한 수치** — 애매한 표현보다 정확한 숫자(검진 항목 수, 소요시간, 공복시간 등).

> 2026 핵심: **"사람이 읽기 전에 AI가 먼저 해석한다."** 따라서 에이전트는 사람 설득용 카피뿐 아니라
> **기계 판독성(구조·근거·수치)**을 동시에 만족시키는 글을 생성해야 한다. (SEO를 넘어 AEO/GEO 관점)

### 2.3 로컬(플레이스) 연계
- 검진·내과는 **지역 검색**이 압도적이다. 블로그 글은 **네이버 플레이스(병원 등록정보)·지도·예약**과 연결.
- 글 안에 위치/동선/주차/진료시간을 **정확한 정보로** 제공해 로컬 신뢰 신호를 보강한다.
  (단, 후기형·유도형 서술이 되면 의료광고법 위반 위험 — 3장 참조.)

## 3. ⚠️ 의료광고법 컴플라이언스 (성능보다 우선하는 하드 제약)

건강검진·내과 콘텐츠에서 **가장 큰 리스크**다. 위반 시 병원(의료인)에게 책임이 귀속된다.

### 3.1 반드시 지킬 금지선 (의료법 제56조 등)
- **치료경험담/후기 광고 금지** — 특정 병원에서 진료받은 구체적 경험·예후를 서술하면 위법 소지.
  대가 수수 여부와 **무관하게**, 위치·연락처·영업시간을 곁들여 내원 유도하면 위반 가능성이 커진다.
- **치료효과 오인 유발 표현 금지** — "완치", "부작용 없음", "최고/유일", 비교우위 단정.
- **비의료인의 의료광고 금지** — 마케터가 의학적 효과를 단정하는 서술 금지. 의학 판단은 의료인 명의·감수.
- **환자 유인·알선성 표현** 및 **비급여 가격 할인 강조**의 과장 주의.

### 3.2 에이전트 설계에 주는 직접 함의
- **컴플라이언스 게이트를 파이프라인의 필수 통과 관문(fail-closed)으로** 둔다.
  - 룰베이스(금칙어·패턴) + LLM 심사(맥락 판단)의 2단.
  - 위험 문장은 **차단이 아니라 대체 문구를 제안**(예: 후기 → "검진 항목/절차의 일반 정보").
- **콘텐츠 유형을 2트랙으로 분리**:
  - **정보성 트랙**(합법 안전지대): 국가검진 대상·주기, 공복 준비, 검진 항목 설명, 결과 수치 읽는 법 → 성장 엔진.
  - **의료행위 서술 트랙**: 반드시 의료인 감수 로그를 남기고, 사전심의 대상 여부를 체크리스트로 태깅.
- **감사 추적(Audit Trail)**: 모든 발행물에 "생성 → 심사 통과 근거 → 감수자" 로그를 남겨 분쟁에 대비.

## 4. 가장 빠른 성장 전략 (쓰레드 "팔로워 500" → 블로그 목표 재정의)

### 4.1 성공 지표(North Star) 재정의
네이버 블로그에는 팔로워가 없다(이웃/서로이웃은 있으나 성과의 핵심이 아니다). 진짜 목표:

1. **1차 목표(노출)**: 타깃 롱테일 키워드 **상위 10위(1페이지) 진입 글 수**.
2. **2차 목표(유입)**: 월 **검색 유입 순방문수** 및 평균 **체류시간 ≥ 90초**.
3. **3차 목표(전환)**: 블로그 → **예약/전화/톡 상담(DB) 전환 수** — 실제 매출 연결 지표.

> 즉 "팔로워 500"의 등가물은 **"주력 롱테일 키워드 30개 상위노출 + 월 상담 전환 N건"**이다.

### 4.2 90일 성장 플레이북
- **주제 고정(C-Rank 축적)**: 첫 90일은 내과·건강검진 100% 집중. 잡주제 금지.
- **롱테일 선점**: "안양 국가건강검진 병원", "인덕원 위내시경 수면", "평촌 종합검진 비용 항목",
  "안양 직장인 검진 토요일" 등 **지역×검진유형×부가조건** 조합으로 대형 키워드 회피.
- **발행 리듬**: 주 3~4회, 같은 시간대. C-Rank의 "꾸준함" 신호 확보.
- **문서 품질 규격(발행 체크리스트)**:
  - [ ] 1,500~2,000자, 목차/소제목/표 포함
  - [ ] 직접 촬영 사진 6~13장(원내 동선·장비·검진 흐름 — 환자 식별정보 없이)
  - [ ] 15초+ 동영상(모먼트) 1개
  - [ ] 검증 가능한 수치(항목 수, 공복 8시간 등) 명시
  - [ ] 컴플라이언스 게이트 통과 로그
- **체류시간 설계**: 도입부 3초 훅 → 목차로 스캔 유도 → 중간 표/체크리스트로 스크롤 지속 → 말미 FAQ.
- **로컬 연계**: 플레이스 정보 일치, 지도·예약 링크(유도형 서술은 배제).

## 5. AI 에이전트 기술 아키텍처

### 5.1 상위 구조 (모듈)
```
                     ┌──────────────────────────────────────────────┐
                     │            Orchestrator (LangGraph)          │
                     │   상태머신: 계획→생성→심사→발행→측정→학습     │
                     └───────┬───────────────────────────┬──────────┘
                             │                           │
        ┌────────────────────▼─────┐          ┌──────────▼───────────────┐
        │  1. Insight/Keyword Engine│          │  4. Compliance Gate       │
        │  - 네이버 검색/데이터랩    │          │  - 룰베이스 금칙어         │
        │  - 경쟁 상위글 분석        │          │  - LLM 의료광고법 심사     │
        │  - 롱테일 키워드 스코어링  │          │  - 대체문구 제안(fail-closed)│
        └────────────────────┬─────┘          └──────────┬───────────────┘
                             │                           │
        ┌────────────────────▼─────┐          ┌──────────▼───────────────┐
        │  2. Content Generator     │          │  5. Publisher             │
        │  - HyperCLOVA X / Claude  │          │  - 초안→(의료인 감수)→발행 │
        │  - 페르소나·톤 프롬프트    │          │  - 예약 발행/이미지 첨부   │
        │  - 구조화(목차·표·수치)    │          │  - Human-in-the-loop 승인 │
        └────────────────────┬─────┘          └──────────┬───────────────┘
                             │                           │
        ┌────────────────────▼───────────────────────────▼───────────────┐
        │  3. Asset Module: 원내 사진/동영상 큐레이션(환자 비식별 검증)      │
        └─────────────────────────────────────────────────────────────────┘
                             │
        ┌────────────────────▼─────────────────────────────────────────────┐
        │  6. Analytics & Feedback Store                                    │
        │  - 순위 트래킹(키워드별 SERP), 체류시간, 유입, 전환(DB), 이탈률     │
        │  - Vector DB(과거 발행물·성과 임베딩) + 지표 DB(시계열)            │
        └────────────────────┬──────────────────────────────────────────────┘
                             │  ← 7. Evaluator/Loop Controller (6장)
                             ▼
                       전략 파라미터 갱신 → Orchestrator로 피드백
```

### 5.2 모듈별 역할
1. **Insight/Keyword Engine** — 네이버 검색/데이터랩·자동완성·연관검색어 수집, 상위 경쟁글 구조 분석,
   `기회점수 = 검색량 × 전환의도 ÷ 경쟁강도`로 롱테일 키워드 우선순위 산출.
2. **Content Generator** — 페르소나/톤/구조 규격을 시스템 프롬프트로 고정. **RAG**로 병원 실제 정보
   (검진 항목·가격정책·의료진 프로필)를 주입해 환각 방지. 초안은 항상 "검증 가능한 수치" 슬롯을 채우도록 강제.
3. **Asset Module** — 원내 촬영본에서 환자 식별정보(얼굴·차트·명찰) 자동 검출·마스킹 검증 후 6~13장 선별.
4. **Compliance Gate**(3장) — **fail-closed** 필수 관문. 통과 근거를 로그로 저장.
5. **Publisher** — 의료 서술 트랙은 **Human-in-the-loop(의료인/책임자 승인)** 후 발행. 예약 발행·발행 리듬 관리.
6. **Analytics & Feedback Store** — 키워드별 순위, 체류시간, 유입, 전환, 이탈률을 시계열로 축적. 발행물·성과를 임베딩.
7. **Evaluator/Loop Controller** — 6장. 성과를 판별해 전략 파라미터를 갱신, 루프를 닫는다.

### 5.3 일일 키워드 순위 트래커 (Daily Rank Tracker) ⭐
> "매일매일 키워드별로 상위노출되는지 얘가 스스로 체크해야 하지 않나" — **맞다. 이게 루프의 눈(센서)이다.**
> 순위는 하루 단위로 출렁이므로, 발행 후 한 번 보는 게 아니라 **매일 자동 측정 → 시계열로 축적**해야
> "언제 진입했고, 유지되는지, 밀려났는지"를 판별할 수 있다.

**동작 방식**
1. **키워드 워치리스트**: 발행한 글마다 타깃 키워드 1~3개를 등록 → 병원 전체 워치리스트로 관리(예: 30~100개).
2. **매일 새벽 배치(예: 06:00)**: 각 키워드로 네이버 검색 → 블로그/통합검색 탭에서
   **우리 글의 순위(1~N위), 노출 페이지, 노출 유무**를 수집. 미노출은 `rank=null`로 기록.
3. **시계열 저장**: `(date, keyword, url, rank, tab, 노출영역)` 형태로 매일 1행씩 적재.
4. **파생 지표 자동 계산**:
   - `상위노출 여부` = 1페이지(≤10위) 진입 T/F
   - `진입 소요일` = 발행일 → 최초 1페이지 진입까지 걸린 일수
   - `순위 안정성` = 최근 7일 순위의 변동성(표준편차)
   - `이탈 감지` = 3일 연속 하락 또는 1페이지 → 이탈 시 알림

**알림/자동 액션 (트래커 → 루프 연결)**
| 감지 이벤트 | 자동 행동 |
|---|---|
| 신규 1페이지 진입 | 성공 라벨링 → few-shot 템플릿 후보로 승격 |
| 순위 급락(3일 연속↓ / 페이지 이탈) | L1 리라이트 큐에 자동 등록 + 담당자 알림 |
| 경쟁사가 우리 위로 진입 | 해당 경쟁글 구조 자동 분석 → 보강 포인트 제안 |
| D+14 미진입 | "리라이트 후보", D+28 미진입 → "폐기/통합 후보" |

**리스크·주의**
- 순위는 **개인화·지역화·시점**에 따라 달라진다 → 로그인/지역 조건을 고정(비로그인·안양 지역 기준 등)해 **측정 조건을 일관**되게.
- 대량·고빈도 크롤링은 정책 위반·차단 위험 → **저빈도(1일 1회)·정중한 수집** 또는 순위 트래킹 상용 API 활용.
- 하루치 스냅샷은 노이즈 → **7일 이동평균**으로 추세를 보고, 단일 급등락에 과반응 금지.

> 요약: **트래커는 매일 돌지만, 판정(L1)은 D+7/14/28 게이트에서** 이동평균 기준으로 내린다.
> "매일 측정, 주기적으로 판단" — 이래야 노이즈에 휘둘리지 않고 루프가 안정적으로 닫힌다.

### 5.4 기술 스택 제안
- **오케스트레이션**: LangGraph(상태머신·HITL·재시도에 적합) 또는 자체 상태머신.
- **LLM**: 한국어·네이버 친화 문체는 **HyperCLOVA X**를, 추론·심사·평가 로직은 **Claude(Opus/Sonnet)**를 혼용.
  (컴플라이언스 심사·평가자 역할은 강한 추론 모델, 대량 초안 생성은 비용 효율 모델.)
- **데이터**: 지표 시계열(PostgreSQL/TimescaleDB) + 임베딩(pgvector/Chroma).
- **수집**: 네이버 오픈API(데이터랩·검색) 우선, 순위 트래킹은 정책 준수 범위에서 자체 SERP 체크.
- **HITL/승인**: 슬랙/노션 승인 큐(이 세션의 MCP 커넥터 활용 가능).

## 6. 클로즈드 루프 평가 알고리즘 (핵심)

> 질문의 핵심: "현재 알고리즘/에이전트 구성이 효과적인지, **어떤 주기로 어떻게 판별**할지."
> 답: **단일 루프로는 부족하다.** 신호가 도착하는 시간축이 다르기 때문에 **3중 루프(3-tier)**로 나눈다.

### 6.1 왜 3중 루프인가 (타당성의 근거)
네이버 상위노출은 **발행 직후가 아니라 수 일~수 주에 걸쳐 순위가 확정**된다. 전환(DB)은 더 늦게 쌓인다.
따라서 "빠른 신호"로만 판단하면 노이즈에, "느린 신호"만 보면 반응이 늦다. → **속도별로 층을 나눈다.**

| 루프 | 주기 | 보는 신호(속도 빠름→느림) | 판별/행동 |
|---|---|---|---|
| **L1 콘텐츠 루프** | 발행 후 **D+7 / D+14 / D+28** | 초기 노출·체류시간·이탈률·순위 진입 여부 | 개별 글 리라이트/보강/폐기 |
| **L2 채널 루프** | **주간** | 상위노출 글 수, 주제 집중도, 발행 리듬 준수, 유입 추세 | 키워드 포트폴리오·발행 계획 조정 |
| **L3 전략 루프** | **월간** | 전환(DB)·C-Rank 성장·CAC·컴플라이언스 위반 0건 | 페르소나/톤/전략 파라미터·모델 프롬프트 개편 |

### 6.2 판별 지표와 합성 스코어
각 글/채널을 **CVI(Content Value Index)**로 요약해 의사결정을 자동화한다.

```
CVI = w1·노출점수      (타깃 키워드 SERP 순위의 역수, 1페이지 진입=강가중)
    + w2·체류점수      (평균 체류시간 / 90초, 상한 클리핑)
    + w3·인게이지먼트  (스크롤깊이·댓글·공감·저장, 이탈률은 감점)
    + w4·전환점수      (예약/전화/톡 상담 = 최상위 가중)
    − p1·컴플라이언스위반  (위반 시 대형 페널티, 사실상 게이트)
```
- **가중치 w는 고정하지 않는다.** L3(월간)에서 "무엇이 실제 전환과 상관됐는지" 회귀/상관으로 재추정 →
  루프가 스스로 목적함수를 보정한다. (예: 체류시간이 전환을 못 끌면 w2를 낮춤.)

### 6.3 "효과 있는가"를 판별하는 규칙 (의사결정 로직)
- **개별 글(L1)**:
  - D+14에 타깃 키워드 **1페이지 미진입 & 체류 < 60초** → **리라이트 후보**(제목·훅·구조·이미지 보강).
  - D+28에도 미진입 → **폐기/통합**(유사 저성과 글을 하나의 강한 글로 병합).
  - 1페이지 진입 & 체류 ≥ 90초 → **성공 템플릿으로 라벨링**, 프롬프트 few-shot 예시로 승격.
- **채널(L2)**: 주제 집중도 < 80% → 잡주제 발행 차단. 발행 리듬 미달 → 스케줄 강화.
- **전략(L3)**: 아래 6.4의 통계 검정으로 "전략 변경이 실제 개선인지" 판정.

### 6.4 인과 판별: 상관을 넘어서기 위한 실험 설계 (⭐ 타당성의 핵심)
순위 변동은 계절·경쟁사·네이버 업데이트 등 **교란요인**이 많다. "우리 전략이 좋아서 오른 것"인지
"운"인지 구분하려면 **대조가 필요**하다.

- **A/B(멀티암드 밴딧)**: 같은 키워드군에서 제목/구조/톤 변형을 나눠 발행, 성과 좋은 팔을 점진 강화.
- **홀드아웃**: 일부 키워드군은 의도적으로 "구버전 전략" 유지 → 신전략과 **차이가 통계적으로 유의한지** 검정.
- **변화점 탐지**: 네이버 알고리즘 업데이트 시점을 외생 이벤트로 마킹, 그 전후를 분리해 오해석 방지.
- **최소 표본 규칙**: 글 몇 개로 결론내지 않는다. 키워드군당 최소 n개·기간 조건 충족 전에는 "판정 보류".

### 6.5 루프 종료·에스컬레이션 조건 (안전장치)
- **컴플라이언스 위반 1건 = 즉시 발행 중단 + 사람 검토**(자동 루프보다 우선).
- **성과 정체가 2개 L3 주기 연속** → 자동 튜닝 중단, 사람에게 "전략 재설계" 에스컬레이션.
- **모델 드리프트/환각 급증** → 생성 롤백, 마지막 안정 프롬프트로 복귀.

## 7. "이 아이디어, 타당한가?" — 비판적 검토 (요청하신 판단)

**결론: 방향은 타당하고 루프로 돌릴 수 있다. 단, 아래 4가지를 지켜야만 성립한다.**

### 7.1 타당한 이유
- 네이버 상위노출은 **측정 가능한 신호(순위·체류·전환)로 환원**되므로, 목적함수화 → 최적화 루프가 실제로 가능하다.
- 콘텐츠 생성은 LLM이 잘하는 영역이고, "구조화·수치·톤"은 규격화가 쉬워 **에이전트가 반복 개선하기 적합**하다.
- 3중 루프는 "빠른 신호로 튜닝, 느린 신호로 방향 검증"이라는 정석 구조라 **과적합·조급한 결론을 방지**한다.

### 7.2 반드시 경계할 4가지 (안 지키면 루프가 무너짐)
1. **의료광고법이 성능보다 위**다. 후기·치료효과형 콘텐츠는 단기 성과가 좋아 보여도 **법적 리스크가 사업을 끝낼 수 있다.**
   → 컴플라이언스는 최적화 대상이 아니라 **불변 제약(hard constraint)**으로 고정.
2. **플랫폼 종속 리스크** — 네이버가 알고리즘을 바꾸면 목적함수가 흔들린다. → 변화점 탐지 + 사람 개입 필수.
   순위 신호는 **자체 추정치**임을 인정하고 과신 금지.
3. **인과 ≠ 상관** — 순위가 올랐다고 우리 전략 덕이라 단정하면 안 된다. → 홀드아웃/실험(6.4) 없이는 "효과 판정"을 신뢰 불가.
4. **진짜 KPI는 순위가 아니라 예약(전환)** — 상위노출돼도 상담 전환이 없으면 실패다.
   유입만 늘리는 국소최적에 빠지지 않도록 **전환을 최상위 가중**으로.

### 7.3 잠재적 실패모드
- **콘텐츠 동질화**: 에이전트가 성공 템플릿만 반복 → C-Rank의 원본성 신호에서 오히려 감점. (다양성 패널티 필요)
- **완전 자동화 과신**: 의료 도메인은 HITL(의료인 승인)이 빠지면 안 된다. **반자동이 정답**.
- **단기 지표 착시**: 체류시간·노출만 좋아지고 전환은 정체 → w 재추정으로 교정.

## 8. 결론 & 다음 단계

- 요청하신 **"에이전트를 루프로 돌린다"는 구상은 타당**하다. 단 **컴플라이언스 게이트(3장) + 3중 평가 루프(6장) +
  인과 검증(6.4) + 전환 최상위 KPI(7.2)** 네 가지가 동반될 때만 안전하고 효과적으로 성립한다.
- 다음 단계 제안:
  1. **MVP 범위 확정**: 롱테일 키워드 10개 + 정보성 트랙만으로 4주 파일럿(발행 12~16건).
  2. **컴플라이언스 룰셋 v1** 작성(금칙어·패턴·대체문구 사전).
  3. **일일 키워드 순위 트래커(5.3) 먼저 가동** — 워치리스트 10~30개로 매일 순위 스냅샷 축적(루프의 눈).
  4. **지표 파이프라인**(순위·체류·전환) 최소 버전 구축 → CVI 계산 자동화.
  4. **L1/L2 루프 먼저 가동**, 데이터가 쌓이면 L3(가중치 재추정·실험)로 확장.
